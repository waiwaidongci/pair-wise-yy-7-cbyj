# 古船模型帆索复核台

运行：

```bash
npm start
```

访问 `http://localhost:3038`。数据保存在 `data/model-rigging-calibration.json`。

## 业务规则

- 每个模型最多只有一项**未闭环**索具任务；任务闭环后才能新增下一项。
- 任务严格按 **待检查 → 调整中 → 待复核 → 已闭环** 推进，服务端校验，不能跳步。
- 调整中提交松紧，只会生成**一条待复核修订**；索具位置等锁定参数不变。待复核期间重复提交沿用首次修订（幂等，不产生新修订）。
- 复核**通过**才用修订值替换当前值，旧值归档进任务历史；**驳回**则修订作废、原值继续有效，任务回到调整中。
- 模型**比例**或**交付日期**变更后，未闭环任务按新参数重核：重回待检查、参数版本递增、待复核修订标记为“参数失效”；旧结论失效但历史可查。已闭环任务不受影响。
- 模型状态由未闭环任务派生（无任务时为待检查，全部闭环为已闭环），列表、筛选、统计、刷新均以服务端数据为准，保持一致。

## 接口

- `GET /api/items` 模型列表（含派生状态、任务、修订与历史）
- `POST /api/items` 建档模型
- `PATCH /api/items/:id` 更新模型参数（比例/交付日期变更触发重核）
- `POST /api/items/:id/tasks` 新增索具任务
- `POST /api/items/:id/tasks/:tid/transitions` 任务动作：`start` / `adjust` / `approve` / `reject`
- `GET /api/stats` 各状态模型数量
